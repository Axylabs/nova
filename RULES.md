# RULES.md — @ignex/nova

Non-negotiable rules for writing code in this repo. Read before editing.
Enforced by convention, lefthook (pre-commit/pre-push), and CI
(`bun run verify`). `AGENTS.md` is the how-to guide; `.agents/skills/` holds
task-specific runbooks; `docs/ai/LOCAL_DEV.md` covers cross-repo local dev.

## 1. Bun first — Rust core first

- nova is a **Bun-only** package (`engines.bun >= 1.4`, the Rust-based
  runtime — [bun.com/blog/bun-v1.4](https://bun.com/blog/bun-v1.4)); the
  server uses `Bun.serve` + `bun:ffi`, the browser client is plain TS. There
  is **no Node compatibility layer** — don't add one.
- **Performance comes from the Rust core** (`rust/`, the `ignex_ffi`
  cdylib). The direct-FFI encode path is the hot path; the JSON/pure-JS paths
  are fallbacks. Before writing a TS hot loop, check whether it belongs in
  `rust/src/` or the generated encoders. Perf is gated by `bench/BASELINE.md`
  (>5% drift on the gate numbers is a failure).

## 2. FFI to Rust: `cstring` / zero-text-encoding — never hand codecs

- **Strings into Rust**: `cstring` FFI arg + `CStr::from_ptr` — Bun's engine
  transcodes the JS string to a call-scoped NUL-terminated UTF-8 buffer
  (**zero JS-side `TextEncoder`/`TextDecoder`**). Never dereference past the
  NUL; embedded-NUL inputs route to the JSON path.
- **Bytes**: `(ptr, len)` / `buffer`/`buffer_length` pairs — TypedArray →
  pointer engine-side (zero-copy), `slice::from_raw_parts` on the Rust side.
- Every `extern "C"` export: `panic_guard` (`catch_unwind` → fallback; a
  panic through `extern "C"` kills Bun), null-check every pointer,
  needed-size convention (`0` = error, `w > out_cap` = exact size),
  `thread_local` scratch only (no global `static mut`).
- ABI types in the `dlopen` map MUST match the Rust signature exactly — a
  mismatch is a crash, not an error. The bind-time self-test
  (probe magic → wire version → schema fingerprint → frame invariant →
  per-symbol) is the net; failing symbols disable and fall back.

## 3. Generated code discipline

- **NEVER hand-edit `src/generated/`, `rust/src/generated/`, or
  `rust/src/transcode/generated.rs`** — they are regenerated by
  `bun run generate` from `src/schema/index.ts`. Change the schema or the
  emitters (`src/codegen/*`), then regenerate and commit the output.
- Keep codegen emitters and generated output in sync; `src/generated/
  wire-registry.json` is the machine-readable contract for external consumers.

## 4. Functional composition — pure functions, no classes

- Public API = **functional composition over an explicit state object**:
  composition roots `src/core/server/` + `src/core/client.ts`; action
  modules (`auth`, `rooms`, `replay`, `groups`, `backpressure`, `outbound`,
  `routing`, client-*) are pure-ish `(state, …) => …` functions; factories
  (`createMetrics`, `createScratch`, `createStats`) own encapsulated state.
  No classes, no `this`, for public surfaces. `int64-guard` stays a
  module-global by design.
- **Small functions in small files**: one responsibility per file, grouped
  into folders by concern (`src/core/`, `src/transport/`, `src/bindings/`,
  `src/bridge/`, `src/events/`). Follow the existing decomposition.

## 5. Structure & maintainability

- New code ships in small, focused files under the right folder — consult
  `docs/architecture.md` + `docs/ai/TREE.md` before adding a file.
- Don't reinvent: nova is independent of other `@ignex/*` packages (no
  imports — see `docs/ai/LOCAL_DEV.md` for when that changes). Check
  `src/` before writing a new helper.
- `public/*.ts` shims keep npm subpaths + `dist` stable — edit `src/core`,
  not `public/`.

## 6. Tests ship with code

- `bun test` (~234 cases across 29 files): api, auth, backpressure,
  bidirectional, bindings-gen, byte-buffer-pool, direct, e2e, efficiency,
  events, events-cluster, ffi, groups, int64, integrity, loader, metrics,
  nats-bridge, nats-integration (opt-in via `NATS_URL`), performance,
  reconnect, ring, rooms, roundtrip, security, security-hardening, targeting,
  trace, wire.
- FFI-backed paths need `bun run generate` + `cargo build --release` first.
- Perf-sensitive changes: re-run `bench:serialize` + `bench:throughput`.

## 7. Docs discipline (anti-hallucination)

- Docs must match code. Never document behavior you did not verify in the
  source; if a doc and the code disagree, fix the doc.
- When you add/rename/move files or exports, update `AGENTS.md`, `RULES.md`,
  the relevant `.agents/skills/`, `docs/*.md`, and regenerate the scaffolding
  map (`bun run gen:ai-map`).
- The npm package name is **`@ignex/nova`** (never `ignex-nova` in install/
  import docs — `ignex-nova` only names the repo/Rust crate).

## 8. Local development with core projects (maintainers & AI only)

- Core IgnEX packages live one directory back in `/home/adeel/poc/`. Use
  `bun link @ignex/nova` (from `../ignex-nova`) when a consumer needs the
  local source — see `docs/ai/LOCAL_DEV.md`. Rebuild the addon
  (`bun run build:rust` / `bun run prebuild`) before linking. Never publish
  from a linked tree; CI/releases resolve from the registry
  (`scripts/release.ts`).
